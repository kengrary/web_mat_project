# MAT 核心算法深挖 + 你的项目落地方案

> 已确认的项目约束：**仅 hprof / 内嵌 Equinox-OSGi / 解析与查询分离部署**。
> 本文聚焦四个对项目最关键的源码模块，并给出对应的落地方案。

---

## A. 解析模块的"蓝本"——其实只有一句话

读 `ParseSnapshotApp.start()`（MAT 命令行 `org.eclipse.mat.api.parse` 的实现），核心解析逻辑就是：

```java
ISnapshot snapshot = SnapshotFactory.openSnapshot(file, arguments, listener);
```

`openSnapshot` 内部会跑完整管线（Pass1/Pass2 → GarbageCleaner → DominatorTree）并把全套 `*.index` 落到 dump 同目录。**解析完成后 index 就在磁盘上了**，后续可被任意进程（你的 Web 后端、甚至 MAT GUI）reopen。

### 你的解析模块（CLI）形态
- 注册为一个 Equinox `IApplication`（照抄 `ParseSnapshotApp` 的结构最省事），或在自己的 main 里启动 headless Equinox 后调用 `SnapshotFactory.openSnapshot`。
- 命令行参数透传给 `arguments` Map，支持：
  - `keep_unreachable_objects` —— 保留不可达对象
  - `snapshot_identifier` —— 多 dump 文件时选哪个
  - `discard_ratio/pattern/offset/seed` —— 超大堆抽样丢弃（实验特性）
- 产物：与 MAT 原生 **完全互通** 的 index 文件集（见 01 文档 §2 清单）。
- 部署：放在大内存机器（参考 MAT 估算 `T ≈ N*28.25 + C*1000 + P` 字节，N=对象数、C=类数）。

## B. 支配树 (Dominator Tree) —— retained size 的根基

文件：`DominatorTree.java`，算法 = **Lengauer-Tarjan**（标志数组 `semi/vertex/label/ancestor/parent/bucket/dom`）。

流程（`Calculator.compute()`）：
1. 构造虚拟超级根 `r`，把所有 GC roots 作为它的后继。
2. `dfs(r)` —— 在 outbound 图上做迭代式 DFS（用显式栈避免递归爆栈），给每个可达对象一个 DFS 序号 `vertex[]`。
3. 主循环 `for i = n..2`：用 semi-dominator + bucket + link/eval(带路径压缩) 求 immediate dominator `dom[]`。
4. 第二轮修正：`dom[w] = dom[dom[w]]`。
5. 把 `dom[]` 写成 `domIn.index`，再由 `FlatDominatorTree` 反转成 `domOut.index`（每个对象→它直接支配的对象集），并自底向上累加得到每个对象的 **retained size**，写 `o2ret.index`。

**关键工程技巧（直接关系到你的内存效率）**：
- 计算前 `outboundIndex.unload()`、计算后 `inboundIndex.unload()` —— **主动卸载索引页释放内存**。支配树需要约 7 个 `int[N]` 数组，是整个解析最吃内存的阶段。
- 你的 Web 后端**不需要重算支配树**：直接读已落盘的 `domIn/domOut/o2ret` 即可，retained size 是 O(1) 查表。

对应 ISnapshot API：`getImmediateDominatorId` / `getImmediateDominatedIds` / `getRetainedHeapSize` / `getTopAncestorsInDominatorTree`。

## C. Retained Set —— 任意对象集合的"独占保留"

文件：`SnapshotImpl`（`getRetainedSet` 系列，约 777 行起）。算法不靠支配树子树，而是用**标记-清除式可达性**：
1. 把目标集合标记为"已访问"。
2. 从所有 **GC roots** 出发遍历，凡能绕过目标集合到达的对象都标记。
3. 遍历结束后**仍未被标记**的对象 = 只能经由目标集合到达 = retained set。
4. 也提供 `getMinRetainedSet` / `getMinRetainedSize`（基于支配树的快速近似/精确变体）。

> 含义：这正是 MAT UI 里选中一批对象后 "Show Retained Set" 的后端。Web 后端直接转调即可，是图遍历，**务必放后台任务/带超时**，不要阻塞请求线程。

---

## D. GC Root 路径查找 —— Leak 分析的核心视图

文件：`MultiplePathsFromGCRootsComputerImpl.java`。
- 算法 = **BFS（广度优先）**，从 GC roots 出发，记录每个对象的 `parent[]`；BFS 保证拿到的是**最短路径**（"shortest path to GC roots"）。
- 提供三种聚合：
  - `getPathsByGCRoot` —— 按 GC root 分组
  - `getAllPaths` —— 所有路径
  - `getPathsGroupedByClass(startFromTheGCRoots)` —— 按类合并（"Merge Shortest Paths"，找泄漏模式最常用）
- 单对象版 `getPathsFromGCRoots(id, excludeMap)` 返回 `PathsFromGCRootsTree`，`excludeMap` 用来排除弱/软/虚引用（避免被无关引用干扰）。

> 这是定位"对象为什么没被回收"的关键。Web 前端做成可展开的引用链树，逐层懒加载。

## E. OQL 引擎 —— 可直接复用的查询语言

目录 `parser/internal/oql/`：
- `parser/OQLParser` 等是 **JavaCC 生成**的词法/语法分析器。
- `compiler/CompilerImpl` 把 AST 编译成可执行 `Query`。
- 入口：`SnapshotFactory.createQuery(String)` → `OQLQueryImpl` → `execute(ISnapshot, listener)`。
- 语法类 SQL：`SELECT * FROM java.lang.String s WHERE s.count > 100`。

> 直接把一个 `/oql?q=...` 端点接到 `createQuery(...).execute(snapshot, listener)`，前端就有了和 MAT 完全一致的 OQL 能力。注意结果可能很大，要分页。

## F. Web 后端落地方案（基于以上 + 你的"分离部署"约束）

### F.1 进程模型
```
[大内存机器]  解析 CLI(嵌 Equinox) → 产出 dump.*.index   ──(拷贝 index + 原始 hprof)──▶
[查询机器]    Web 后端(嵌 Equinox) 启动时 openSnapshot(file)
              · index 比 hprof 新 → 走 SnapshotImpl.readFromFile()，秒级加载
              · 维护 Map<dumpId, ISnapshot>，LRU + 显式 dispose()
```
> 注意：MAT reopen 时**仍需要原始 hprof 文件在场**（读对象字段要 seek 回 hprof）。所以查询机要同时有 `dump.hprof` + 全套 `dump.*.index`。若想完全脱离 hprof，需要额外把字段也物化进 index（MAT 默认不这么做）——这是一个明确的取舍点，建议初期照搬 MAT（带上 hprof）。

### F.2 REST 端点 ↔ ISnapshot 映射（建议首批）
| 端点 | 调用 | UI 对应 |
|---|---|---|
| `GET /snapshots/{id}/overview` | `getSnapshotInfo` | 概览 |
| `GET /snapshots/{id}/histogram?page=` | `getHistogram` | Histogram |
| `GET /snapshots/{id}/classes?name=` | `getClassesByName` | 类筛选 |
| `GET /snapshots/{id}/objects/{oid}` | `getObject` + fields | Inspector |
| `GET /snapshots/{id}/objects/{oid}/outbound` | `getOutboundReferentIds` | outgoing refs（懒加载一层）|
| `GET /snapshots/{id}/objects/{oid}/inbound` | `getInboundRefererIds` | incoming refs |
| `GET /snapshots/{id}/dominator?parent=` | `getImmediateDominatedIds` | Dominator Tree（懒加载）|
| `GET /snapshots/{id}/objects/{oid}/paths2gc` | `getPathsFromGCRoots` | Path to GC Roots |
| `POST /snapshots/{id}/retained` | `getRetainedSet` | Retained Set（后台任务）|
| `POST /snapshots/{id}/oql` | `createQuery().execute()` | OQL |

### F.3 效率对齐 MAT UI 的硬性原则
1. **永不在请求线程做全堆扫描**。histogram / 支配树顶层等聚合结果做进程内缓存（首次算、后续命中）。
2. **树视图严格懒加载**：一次只返回一层子节点（id + shallow + retained + 类名），展开才取下一层 → 直接对应 `getImmediate*` / `get*ReferentIds` 的单层调用。
3. **重计算（retained set / paths / OQL）走异步任务 + 轮询/SSE**，给进度（复用 `IProgressListener`）。
4. **对象 id 是 int**，JSON 里就传 int id 做游标，地址只在详情里给（`mapIdToAddress`）。
5. snapshot 常驻、复用；用引用计数/LRU 控制同时打开的 dump 数（每个约 `N*28.25+C*1000` 字节）。

## G. 工程化注意事项（嵌 Equinox 的坑）

1. **extension registry 必须可用**：parser、query、report 都靠它发现实现。最稳妥是用 `org.eclipse.equinox.launcher` 或 `org.eclipse.core.runtime` 以 headless 方式起一个最小 OSGi 容器，确保 `org.eclipse.mat.hprof` / `.parser` / `.api` / `.report` bundle 被加载。
2. **bundle 集合（最小）**：`org.eclipse.mat.api` `.report` `.parser` `.hprof`（+ collect 在 report 内）+ Equinox 核心。**排除** `.ui` `.ui.rcp` `.chart`（SWT）。
3. **Java 版本**：parser bundle 要求 JavaSE-1.8，api bundle 新版要求 JavaSE-21；当前沙箱是 JDK 11。建议生产用 **JDK 17/21**（与最新 MAT 对齐）。
4. **许可证 EPL-2.0**：复用/链接没问题；分发要附带 license 与（如修改）源码义务。
5. 线程安全：`IndexReader` 用 `ConcurrentHashMap` 缓存页、`SimpleBufferedRandomAccessInputStream` 上有锁；`ISnapshot` 多数读操作可并发，但重计算应串行化或各自独立。

## H. 建议的实施顺序（里程碑）

1. **M0 环境**：拉 MAT 1.15.x release jar（或用源码 Maven/Tycho 构建），跑通命令行 `org.eclipse.mat.api.parse dump.hprof` 产出 index —— 验证复用可行。
2. **M1 解析 CLI**：包装成自己的 CLI（嵌 Equinox），参数透传，产出 index。
3. **M2 后端骨架**：嵌 Equinox + `openSnapshot` 加载已存在 index + `/overview` `/histogram` 两个端点。
4. **M3 树视图**：outbound/inbound/dominator 懒加载端点 + 前端树组件。
5. **M4 高级**：paths2gc、retained set（异步）、OQL。
6. **M5 报告**：复用 `org.eclipse.mat.api` 的 Leak Suspects / Top Components（report 引擎）。

> 当前沙箱无 Maven 且 MAT 用 Tycho 构建（依赖 p2/OSGi），无法在此直接编译整个 MAT。M0 起需要在你本地用 Tycho 或直接下载 MAT 发行版 jar。源码我已克隆在 `mat-src/`，可继续随时查阅任何实现细节。
